# Screenshots

Stills pulled from the encoded cut with
`ffmpeg -ss <t> -i docs/demo.mp4 -frames:v 1 <name>.png`, so each one shows exactly what
the video shows at that second - drawn from the captured handler ledger, not mocked up.

| file | at | what it is |
| --- | --- | --- |
| `lane-spec.png` | 30s | `reaper_lane uk-drill` - tempo, key, drums, low end, harmony, vocal, the ARC, and the section plan with bar counts and an energy map |
| `deliverable.png` | 50s | `reaper_block ghetto-blues` - the pasteable deliverable in Suno's field order, with the fitted character counts |
| `validator-verdict.png` | 66s | `reaper_check` on a real finished draft - both limits measured, 0 issues |
| `lane-sweep-41of41.png` | 88s | the sweep: all 41 lanes built and gated in one pass |

Rebuild the whole cut:

```bash
python3 scripts/demo_render.py html
python3 scripts/demo_render.py capture --start 0 --end 2835   # 94.5s of timeline at 30fps
python3 scripts/demo_render.py encode
```

Then re-extract the stills with the timestamps above. The renderer refuses to run without
`docs/evidence/demo_scenes.json`, so a still can never drift from the ledger it came from.

## The submission cut (88s, scored)

`docs/demo-song.mp4` is the **same timeline** as `docs/demo.mp4`, sampled 1.0738636x faster
(94.5s -> 88.0s, 2640 frames) and scored with the track the desk's own spec produced. The
Hermes plugin hackathon asks for a demo under 90 seconds, and resampling keeps every scene,
string and panel identical — only the clock is faster — instead of dropping content to fit.

```bash
python3 scripts/demo_render.py capture --start 0 --end 2640 --scale 1.0738636 \
  --frames-dir /opt/data/cache/scratch/rr-render/frames-88
python3 scripts/demo_render.py encode --out docs/demo-song.mp4 \
  --frames-dir /opt/data/cache/scratch/rr-render/frames-88
# scoring (mux) command and the alignment reasoning: docs/song/forty-one-lanes.md
python3 scripts/demo_render.py proof --out docs/demo-song.mp4   # regenerates the proof from the file
```

The four stills above are frames of the silent authored cut at the timestamps listed; the 88s
cut shows the same frames, earlier. `docs/evidence/demo-song_proof.json` is generated by
`ffprobe` from the delivered file, including its audio stream, so nothing here is hand-typed.
